# Locator Lense MVP Requirements

## 1. Summary

Locator Lense accepts exactly one input source: an HTTP/HTTPS webpage URL or raw HTML content. It analyzes the server-delivered HTML DOM and generates an HTML report containing visible headings, subheadings, and interactable elements with metadata and a preferred locator.

The MVP analyzes static HTML only. It does not execute JavaScript or analyze dynamically injected content.

## 2. Functional Requirements

### Input and Page Retrieval

1. The system shall accept either a webpage URL or raw HTML content.
2. The system shall require exactly one input source and reject submissions containing both URL and raw HTML.
3. The system shall support `http://` and `https://` URLs.
4. The system shall automatically follow standard HTTP redirects.
5. The system shall analyze the final resolved URL and include it in the report.
6. A URL shall be marked unavailable only when the final destination cannot be reached or returns an error.

### HTML Analysis

7. The system shall analyze only the server-delivered HTML DOM.
8. The system shall not execute JavaScript in the MVP.
9. JavaScript-rendered or dynamically injected content may be excluded.
10. The system shall identify visible elements only.
11. The system shall identify:
   - `<h1>` headings.
   - `<h2>` through `<h6>` subheadings.
   - Elements with ARIA heading roles.
   - Links, buttons, inputs, selects, and textareas.
   - Elements with roles `button`, `link`, `tab`, `menuitem`, or `option`.
   - Elements with `tabindex >= 0`.
12. An element matching multiple extraction rules shall be reported once.
13. Visible text shall be normalized by trimming leading and trailing whitespace and collapsing consecutive whitespace into one space.

### Element Metadata and Styles

14. For each extracted element, the report shall display:
   - Element category.
   - Normalized visible text.
   - Tag name.
   - Preferred locator.
   - Locator type.
   - Locator match count.
   - Locator score.
   - Font family.
   - Font size.
   - Text color.
   - Relevant attributes when available.
15. Relevant attributes shall include, when available: `id`, `name`, `class`, `role`, `href`, `type`, `value`, `placeholder`, `aria-label`, `aria-labelledby`, `data-testid`, and `tabindex`.
16. The system shall extract style metadata from inline styles and directly retrievable linked CSS declarations.
17. Fully computed browser styles are not required.
18. If a style value cannot be reliably determined through static analysis, the report shall show `Not available`.

### Locator Generation

19. The system shall generate one preferred locator for each extracted element.
20. Locator preference order shall be: `id`, `name`, `data-testid`, CSS Selector, XPath.
21. A locator shall be unique when it matches exactly one element in the analyzed DOM.
22. Unique locators shall always be preferred over non-unique locators.
23. The system shall use these fixed base scores:
   - `id`: 100
   - `name`: 90
   - `data-testid`: 85
   - CSS Selector: 75
   - XPath: 65
24. A unique locator shall retain its base score.
25. A non-unique locator shall retain the base score for its locator type and be marked `Non-Unique`.
26. If no unique locator is available, the system shall select the highest-priority locator according to the preference order.
27. If multiple locators have the same type, the system shall prefer the one with the lowest match count.
28. The selected locator, locator type, match count, and final score shall be included in the report; alternative locators shall not be included.
29. CSS selectors shall be as short and stable as possible while uniquely identifying the element when feasible.
30. CSS selector generation shall prefer stable attributes, avoid volatile or autogenerated class names where possible, and use structural selectors as a fallback.
31. XPath shall be used only as a last fallback.

### Report

32. The system shall generate an HTML report page.
33. The report header shall display `Locator Lense`.
34. The report shall display information about the reported page, including its title, final resolved URL when applicable, and detected technology stack.
35. Technology detection shall be best-effort using signals available in the supplied HTML and directly available page resources.
36. The report shall show `Not detected` when the technology stack cannot be determined.
37. The report shall contain a table listing all extracted elements and their metadata.
38. The report shall clearly indicate missing metadata, unavailable URLs, no matching elements, and non-unique locators.
39. Empty input and invalid URLs shall be handled gracefully.

## 3. Non-Functional Requirements

1. The MVP should remain lightweight and performant by analyzing static HTML only.
2. Locator generation shall be deterministic for the same HTML input.
3. Malformed or untrusted input shall not break report generation.
4. The report shall remain readable when metadata is missing or unavailable.
5. URL failures shall produce a usable error report rather than an unhandled application error.
6. The MVP shall support HTML documents of reasonable payload size.

## 4. Assumptions

1. `Locator Lense` is the exact application name shown in the report.
2. Only the final HTML response is analyzed for URL inputs.
3. Visibility is determined from statically available HTML and CSS information.
4. CSS declarations are analyzed only when they can be retrieved directly.
5. Technology detection is best-effort and may return `Not detected`.
6. Locator match counts are calculated against the complete analyzed DOM.
7. Non-unique locators retain their fixed base score and are marked `Non-Unique`.
8. Cross-domain iframe content is not analyzed.

## 5. Edge Cases

1. Empty URL or raw HTML input.
2. Both URL and raw HTML supplied.
3. Invalid URL syntax or unsupported URL scheme.
4. Redirect loop or unreachable final destination.
5. Final URL returning an HTTP error.
6. HTML containing no headings or interactable elements.
7. Elements with empty visible text.
8. Hidden elements matching extraction rules.
9. Duplicate IDs, names, or `data-testid` values.
10. CSS selectors or XPath expressions matching multiple elements.
11. Missing or unavailable linked CSS resources.
12. Missing page title or undetectable technology indicators.
13. Malformed HTML.
14. Elements matching multiple extraction categories.
15. Invalid or non-numeric `tabindex` values.
16. Special characters requiring escaping in generated locators.

## 6. Out of Scope

- Login-protected pages and authentication workflows.
- Crawling multiple pages.
- Screenshot generation.
- Accessibility scoring.
- Cross-domain iframe analysis.
- Full website audits.
- JavaScript execution and browser-rendered DOM analysis.
- Dynamically injected content analysis.
- Full computed-style calculation.
- Redirect-chain reporting.
- Advanced technology detection requiring runtime inspection.

## 7. Open Questions

None. The MVP requirements are approved.
